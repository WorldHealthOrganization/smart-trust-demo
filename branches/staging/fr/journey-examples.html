    La présentation guidée des parcours (racontée d’abord dans l’atelier VaxLink, source) montre des exemples de charges utiles FHIR dans son tiroir de charge utile et sur ses écrans d’appareil S1 à S8. Cette page fait correspondre chacun d’eux à l’exemple de ce guide qui le matérialise.

    Chaque exemple est publié deux fois : sous forme de page, et en JSON brut à une URL stable que la présentation guidée peut récupérer (https://worldhealthorganization.github.io/smart-trust-demo/<Type>-<id>.json). Ils sont en FHIR R4 (4.0.1), comme ce guide, ainsi que smart-base et le guide Personal Health Wallet.

    Profils par pays

    Chaque pays n’enregistre que ce dont sa propre étape a besoin ; le guide comporte donc un petit profil par pays là où les deux diffèrent. La description de chaque profil indique comment il est utilisé dans le parcours et pourquoi ses contraintes existent. Ce sont des profils de démonstration : ils montrent ce sur quoi repose chaque étape et ne constituent pas la spécification nationale d’un ministère.

    Le tiroir de charge utile

    Les clés du MOCK_FHIR_RESOURCES (src/data/storylineData.ts) de la présentation guidée et l’exemple qui remplace chacune d’elles :

    Clé Type Exemple Ce qui a changé
    patient Patient TrustDemoSomsak (json) Le système d’identifiants temporaires est celui de ce guide (http://smart.who.int/trust-demo/sid/onesa-temporary-id), et non une URL ministérielle.
    group Group TrustDemoHousehold (json) actual = true ; les membres sont des Patients (en FHIR R4, Group liste des Patients, donc chaque parent est un Patient à côté de son rôle RelatedPerson) ; le code du ménage est FAMMEMB, avec le texte « Household ».
    immunizationHepB Immunization TrustDemoJ3HepB (json) Les deux codages, comme dans la charge utile de la présentation guidée ; plus le CVX 08. Les systèmes de codes des produits et du calendrier sont des substituts illustratifs propres à ce guide.
    serviceRequest ServiceRequest TrustDemoJ2Referral (json) Le code est SNOMED CT 3457005 (orientation du patient) avec le texte de la présentation guidée ; le motif de vérification reste dans reasonCode.
    provenance Provenance TrustDemoJ3Verification (json) Agents vérificateur, de saisie et auteur ; les DVC comme entités sources et les doses déclarées comme supprimées. La signature COSE reste dans le DVC plutôt que dans Provenance.signature.
    auditEvent AuditEvent TrustDemoJ41Access (json) Forme R4 : type, subtype, outcome, outcomeDesc ; le destinataire est le demandeur, la passerelle du pays Onesa le dépositaire et l’observateur. Le code d’accès n’est jamais journalisé.
    cborPayload (pas FHIR) — La charge utile du DVC est un HCERT (CBOR/COSE), et non une ressource FHIR ; son modèle logique est le DVCMinPreQual de smart-trust-phw. Elle attend le bean ig01 avant de devenir un exemple ici.

    Ce que les exemples modifient par rapport aux copies de la présentation guidée

    • Systèmes de codes. Le produit de chaque dose est codé avec son identifiant de produit WHO PreQual (a3K3X000006MiiXUAS pour la dose de naissance contre l’hépatite B, etc.), issu du système de codes http://smart.who.int/pcmt-vaxprequal/CodeSystem/PreQualProductIds du SMART Product Dataset for Prequalified Vaccines, et le ValueSet TrustDemoVaccineProducts énumère ceux qu’utilisent les parcours ; le produit administré à chaque dose fictive est illustratif. Les codes du calendrier du pays Onesa (XXU-EPI-HEPB-BD, etc.) sont illustratifs et définis ici comme le système de codes TrustDemoOnesaEpiSchedule, marqué comme expérimental, sous l’URL canonique de ce guide, afin qu’aucune URL ne suggère un ministère réel.
    • Pays. Taifafeki est jouée sur le réseau DEV du GDHCN par le participant de test XXR, et Onesa par le participant fictif XXU. Aucune de ces clés n’est une clé de production.
    • Le code d’accès. La présentation guidée affiche 4829 à l’écran. Aucun exemple ne stocke de code d’accès : les enregistrements de consentement et d’audit indiquent seulement qu’un code a été vérifié.
    • Dates. Comme dans la présentation guidée : naissance le 2025-10-28, J2 le 2025-11-18, J3 le 2025-11-25, les doses à Onesa le 2025-12-10 et le 2026-07-28, le voyage le 2026-10-28.
